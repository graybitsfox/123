#### **1. Критическая проблема: Потеря всех NPC при перезапуске**

*   **Файл**: `src/main/java/com/example/intelligentnpc/npc/NPCManager.java`
*   **Метод**: `loadNPCsFromMemory(MinecraftServer server)`
*   **Описание**: Этот метод, который должен вызываться при старте сервера, абсолютно пуст и содержит только комментарий `// TODO: Реализовать загрузку NPC`. Метод `saveAllNPCsToMemory()` работает и сохраняет данные NPC в файлы `.json` при остановке сервера, но так как нет логики загрузки, эти файлы никогда не используются.
*   **Последствия**: Администратор сервера может потратить часы на создание и настройку NPC, но после первого же планового или аварийного перезапуска **все NPC исчезнут**. Это делает мод практически непригодным для использования на постоянных серверах.
*   **Код**:
    ```java
    // src/main/java/com/example/intelligentnpc/npc/NPCManager.java:311
    public void loadNPCsFromMemory(MinecraftServer server) {
        // TODO: Реализовать загрузку NPC из файлов памяти при старте сервера
        // ...
        IntelligentNPCMod.LOGGER.info("NPC loading from memory is not yet implemented");
    }
    ```

##### **2.1. Неработающие команды управления командой NPC**

*   **Файл**: `src/main/java/com/example/intelligentnpc/commands/NPCCommand.java`
*   **Методы**: `createTeam`, `leaveTeam`
*   **Описание**: Команды `/npc team create` и `/npc team leave` зарегистрированы и доступны в игре, но их логика не завершена.
    *   `createTeam`: Просто устанавливает флаг `canLeadTeam` у NPC, но фактически не создает никакой командной структуры.

##### **2.2. Память NPC не загружается**

*   **Файл**: `src/main/java/com/example/intelligentnpc/npc/NPCEntity.java`
*   **Описание**: У NPC есть метод `loadFromMemory()`, который должен восстанавливать его состояние (навыки, личность, опыт) из сохраненного файла. Однако этот метод нигде в коде не вызывается. Даже если бы основная проблема с загрузкой NPC была решена, все NPC появлялись бы с "чистой" памятью, как будто они только что созданы.
*   **Последствия**: Обучение, развитие навыков и накопленный опыт NPC теряются при каждой перезагрузке, что обесценивает одну из ключевых особенностей мода.

##### **2.3. Небезопасное сохранение данных (риск потери)**

*   **Файл**: `src/main/java/com/example/intelligentnpc/npc/NPCMemory.java`
*   **Метод**: `save()`
*   **Описание**: Метод использует `Files.write` для сохранения JSON-файла, но делает это без блока `try-catch`. Если в процессе сохранения произойдет любая ошибка ввода-вывода (`IOException`), например, из-за нехватки места на диске, отсутствия прав на запись или блокировки файла, то приложение "упадет", либо данные будут утеряны без каких-либо сообщений об ошибке в логах.
*   **Последствия**: Внезапная и "тихая" потеря данных о прогрессе NPC. Администратор не будет знать, что произошла ошибка, пока не обнаружит, что NPC "поглупел".
*   **Пример улучшения**:
    ```java
    // Как можно было бы улучшить:
    public void save() {
        try {
            // ... (код для создания Gson и json)
            Files.write(Paths.get(memoryFile.toURI()), json.getBytes());
        } catch (IOException e) {
            IntelligentNPCMod.LOGGER.error("НЕ УДАЛОСЬ СОХРАНИТЬ ПАМЯТЬ для NPC {}: {}", npc.getNpcName(), e.getMessage());
        }
    }
    ```

#### **3. Потенциальные ошибки и узкие места для улучшения**

##### **3.1. Задачи NPC не сохраняются**

*   **Файл**: `src/main/java/com/example/intelligentnpc/npc/NPCBrain.java`
*   **Описание**: "Мозг" NPC хранит текущую цель (например, "строительство") и очередь задач (например, "идти к точке А", "поставить блок Б"). Эти данные хранятся в полях класса, но не являются частью `NPCMemory`.
*   **Последствия**: После перезагрузки NPC забудет, над чем он работал. Если ему дали задачу построить дом, после перезапуска он будет просто стоять без дела, пока ему не дадут новую команду.

##### **3.2. Отсутствие обратной связи от AI**

*   **Файлы**: `BuilderAI.java`, `TradeAI.java` и другие.
*   **Описание**: AI-модули обрабатывают команды, но если команда неполная или невыполнима, они просто молча ее игнорируют. Например, игрок пишет: `"Боб, построй дом"`. `BuilderAI` получает команду, но не знает, *какой* дом строить, и просто ничего не делает.
*   **Последствия**: Игрок не понимает, почему NPC не выполняет его команду, что вызывает разочарование и ощущение, что мод "сломан". NPC должен был бы ответить что-то вроде: *"Какой дом ты хочешь, чтобы я построил?"*

##### **3.3. Недоразвитые AI-модули**

*   **Файлы**: `LearningAI.java`, `SurvivalAI.java`, `TeamAI.java`
*   **Описание**:
    *   `LearningAI`: Позволяет установить "фокус обучения", но сам процесс получения опыта или улучшения навыков со временем никак не реализован.
    *   `SurvivalAI`: Полностью пуст. NPC не будет реагировать на очевидные угрозы, такие как лава, огонь, кактусы или падение с большой высоты.
    *   `TeamAI`: Имеет базовые методы для запроса на вступление в команду, но логика совместной работы (например, помощь в бою, строительство общего проекта) отсутствует.
*   **Последствия**: Функционал, который заявлен в структуре кода, по факту не работает, что может не соответствовать ожиданиям пользователей.

##### **3.4. Жестко закодированные значения ("магические строки")**

*   **Файлы**: `NPCCommand.java`, `NPCChatCommand.java`
*   **Описание**: Списки допустимых задач ("build", "trade", "guard"), настроений ("happy", "sad") и эмоций ("happiness", "anger") зашиты прямо в `switch` и `if` конструкциях.
*   **Последствия**: Чтобы добавить новую задачу или настроение, разработчику придется найти и изменить код в нескольких местах, что неудобно и может привести к ошибкам. Эти значения лучше вынести в константы или перечисления (`enum`).
*   **Пример**:
    ```java
    // src/main/java/com/example/intelligentnpc/commands/NPCCommand.java:391
    private static boolean assignTaskToNPC(NPCEntity npc, String task, String params) {
        switch (task.toLowerCase()) {
            case "build", "строить" -> { /*...*/ }
            case "trade", "торговать" -> { /*...*/ }
            case "guard", "охранять" -> { /*...*/ }
            // ... и так далее
            // Чтобы добавить задачу "фермерствуй", нужно будет дописать сюда новый case.
        }
    }
    ```
